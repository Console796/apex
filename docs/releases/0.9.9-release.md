# Apex 0.9.x-release: plugins and scripting (DRAFT)

> **DRAFT.** This file is written before the release. `0.9.9` in the file name is a placeholder: the real
> version, build number, tag and download names are not known yet, and every `0.9.x` and `<build>` below must
> be filled in at release. 0.9 is **feature complete with release checks open**. Nothing here has been
> released, tagged or built as a release artifact, and `version.txt` is unchanged.

Apex is a native level editor for Source-engine maps, built for the Strata Source (Portal 2: Community
Edition) toolchain. It reads and writes `.vmf` files, edits them in any number of Vulkan viewports,
compiles them with the real Source tools, launches the game, and previews lighting in the editor.
It is written in C++23 with Qt 6 and Vulkan, it runs natively on Linux and Windows, and it is MIT
licensed.

This release completes milestone 0.9, extensibility. Since
[0.8.9](https://github.com/Console796/apex/releases/tag/v0.8.9-release), Apex can load plugins: native
plugins behind a C ABI, and AngelScript script plugins over the same ABI. A third party can add tools,
actions, panels, overlays, importers and asset sources without rebuilding Apex, using a separately
packaged SDK.

> ## Please read this!
>
> **Apex is still unfinished, pre-release software.** It is not a replacement for Hammer yet, and it
> will crash, lose your place, or do the wrong thing.
>
> - **Back up every map before you open it in Apex.** Saving an unmodified file is byte-identical,
>   but edits are not guaranteed to be safe.
> - **Plugins run inside Apex with no sandbox.** A native plugin can do anything Apex can do, and a crash
>   in a plugin crashes Apex. Only install plugins you trust. After a crash inside a plugin the next start
>   names it and offers to disable it, and `apex --no-plugins` starts with none.
> - **Some 0.9 release checks are still open.** The plugin round trip on Windows, the interop check with
>   Strata Hammer, and the plugin ABI check with the Windows compilers have not been run (see "Known
>   limitations and release checks still open"). Treat the Windows plugin build as untested.
> - **Some 0.8 release checks are still open** too (the written outdoor scenario, interop of every 0.8
>   fixture, and the Windows run), as listed in the 0.8.9 notes.
> - **The baked preview is a preview.** It is not VRAD. Compile with VRAD before you judge a map's final
>   lighting.
> - **Only Portal 2: Community Edition has been tested.** Other Source games may work, partly work, or
>   not work at all.
> - **Windows is less tested than Linux.** See below.

## New since 0.8.9

### Plugin ABI

The plugin interface is a C ABI in `include/apex/apex_plugin.h`, with a header-only C++ wrapper in
`include/apex/plugin.hpp` (C++23) that includes only that header and the standard library.

- **One entry point, versioned interface tables.** A plugin exports one function; the host hands it a table
  of interfaces by name and version (for example `apex.tools/1`), and the plugin asks for what it needs.
- **Every struct begins with `struct_size`, has no implicit padding, and array elements stride by their own
  `struct_size`.** Tables grow only by appending, so a plugin built against an older header keeps working
  and a newer plugin can test whether the host has a member before using it. The golden sizes are checked
  in both C and C++ (`tests/plugin_host/abi_layout.inc`).
- **Interfaces in 1.0:** `apex.document/1` (read the document by ID, notifications with ID change sets),
  `apex.tools/1`, `apex.actions/1`, `apex.edit/1` (writes, one undo step per edit), `apex.selection/1`,
  `apex.ui/1` (declarative panels, sections and dialogs), `apex.overlay/1`, `apex.helpers/1`,
  `apex.problems/1`, `apex.io/1` (importers), `apex.jobs/1`, `apex.watch/1`, `apex.vfs/1` (VFS
  providers) and `apex.assets/1` (asset writes). `apex.registration/1` was the 0.9.1 skeleton and is
  superseded by the tool, action and UI interfaces.
- **Threading.** Plugins are called on the main thread except where an interface says otherwise
  (`apex.jobs/1` workers, a VFS provider's `refresh`).
- **Freeze.** **ABI major 1, minor 0 is frozen** at this release (plans/plugins.md D12 and section 11). The major
  changes only for a break and a break needs a release-note entry. From here existing structs never change
  or reorder, tables grow by appending, new interfaces take a new versioned name, and enums only gain
  values. The rules are written for plugin authors in `docs/plugins/versioning.md`, and
  `tools/check_layers.py` enforces that `include/apex/` includes nothing from `src/` and no Qt.

### What landed, by sub-milestone

**0.9.1: Seams and the loader skeleton.** Plugin actions are optional in presets, and a preset keeps `plugin.*`
bindings it cannot resolve as dormant bindings (so saving without a plugin loaded no longer loses them).
A layout keeps a panel it cannot supply as a placeholder pane. `ChangeSet` carries `NodeId`s. Registration
happens only during startup. The fixed action, tool and panel lists became registries with the built-ins
first. A breadcrumb around every plugin callback, safe mode, and `--no-plugins`. A loader skeleton and the
plugin manager. The first Codex review of this work produced 12 findings; they were fixed before the freeze.

**0.9.2: Tools and actions.** `apex.tools/1` and `apex.actions/1`, a host-side `PluginTool` adapter,
suggested bindings, and the `polygon-tool` example.

**0.9.3: Writes, notifications and selection.** `apex.edit/1` with edit operations that map onto the
document's transaction list (the leftover operations arrived after review: geometry, displacement and
others), `apex.selection/1`, `on_changed` notices with ID change sets, `defer`, and per-session tool
instances (a plugin tool's state is no longer shared between editor sessions).

**0.9.4: Declarative UI.** `apex.ui/1`: forms described as data, rendered by a Qt adapter in `ui`. Plugin
panels, material-panel sections and dialogs. The `face-stats` example.

**0.9.5: Overlays, helpers, problems, importers, jobs, file watch.** `apex.overlay/1` (world and screen
overlays), `apex.helpers/1` (entity helpers, including per-face tint), `apex.problems/1`, `apex.io/1` and
the `obj-import` example, `apex.jobs/1` (background work with cancellation), and `apex.watch/1`. Probe P4
measured the per-face tint cost.

**0.9.6: VFS providers and asset writes.** `apex.vfs/1` and `apex.assets/1`. A provider's entries are
**indexed into the VFS** rather than consulted at lookup time, and a provider's `refresh` runs on the
loading worker (probe P3; this differs from the plan's first sketch).

**0.9.7: Script host.** AngelScript 2.38.0, as a plugin over the same ABI, behind `APEX_WITH_ANGELSCRIPT`
(default ON). Script plugins have a manifest, reload when the file is saved, have a 5 s load budget and a
250 ms per-call watchdog. The `stair` example is a script. Probe P5 measured the script host at about 0.77 ms
against a 2 ms budget, and +1.45 MiB. **Probe P2 (how Strata stores a scriptable primitive) was never run**,
so scriptable and persistent primitives were **not built**; primitives remain "adjust last operation".

**0.9.8: Pies, keybinding page, themes.** Pie layouts are stored in presets and edited on a new Pies page.
The Keybindings page groups plugin actions by plugin and shows dormant and suggested bindings. Plugins can ship themes
as `themes/*.json` in their folder; they appear read-only in the theme list with "Duplicate to edit". A
defect in tool-scoped rebinding (a cleared, then rebound tool-scoped Blender binding took Hammer's default
context) was fixed.

**0.9.9: SDK, documentation, freeze.** The `sdk` install component and the
`apex-plugin-sdk-<version>.zip` package (`python3 tools/package.py --sdk`): the headers, a CMake package
(`find_package(ApexPlugin)`, target `apex::plugin_sdk`, helpers `apex_add_plugin()` and
`apex_add_script_plugin()`), the examples, the docs and the license. The `plugin_sdk_out_of_tree` test unpacks
the SDK and builds three examples with no Apex include path. `docs/plugins/` has 22 pages (getting started,
one page per interface, the threading and memory rules, the C++ wrapper, versioning, the examples), and
`tools/check_docs.py` checks that its code snippets are verbatim from the examples and that links stay inside
the folder. The ABI freeze review is plans/plugins.md section 11.

### Examples shipped with the SDK

`hello-tool` (a first tool; it still uses the older shared-state style), `polygon-tool` (a tool that draws a
solid through `apex.edit/1`), `face-stats` (a panel), `obj-import` (an importer) and `stair` (an AngelScript
plugin).

## Known limitations and release checks still open

Release checks that have not run:

- **Windows and MSVC are untested for plugins.** That covers the SDK build, multi-config generators, the
  DLL naming and location rules, and the C++23 flags that `plugin.hpp` needs.
- **P1 (ABI across compilers) has not been run on the Windows compilers.**
- **The D9 round trip has not been run on Windows,** and so has not been reviewed by the owner.
- **The interop check with Strata Hammer has not been run.**
- **AngelScript has only been built on Linux.** Other platforms are unchecked.
- **Renderer paths are untested without a headless Vulkan device.** Overlay and helper drawing is
  covered by tests only where a device exists.
- **One unexplained one-off failure** was seen in the P1 test group and did not reproduce.

Limitations in what was built:

- **Scriptable and persistent primitives are not built.** Probe P2 was never run, so primitives stay
  "adjust last operation". Strata's AngelScript primitives are not read or written.
- **Floating plugin panels are not supported.** Plugin panels dock only.
- **No native hot reload.** Restart to load or unload a native plugin. Script plugins reload on save.
- **The native Qt panel tier is not shipped.** Panels are declarative.
- **Scripts are single-file.** A script plugin is one `.as` file.
- **No script bindings for the new edit operations.**
- **No read API for displacements or connections** (writes exist, reads do not).
- **Importers use plain host paths,** not the VFS.
- **Helper output does not follow a live drag.** It updates when the drag commits.
- **Empty-body script loops cannot be interrupted** by the 250 ms watchdog.
- **A timed-out provider thread is leaked.** A VFS provider that never returns keeps its thread.
- **The polling file watch can merge two quick saves** into one notice.
- **VMT writes can leave stale material thumbnails.**
- **Suggested bindings are keyed by preset name,** so a copied or renamed preset does not inherit them.
- **Rebinding a plugin's suggested tool-scoped action loses its tool scope.**
- **A plugin theme falls back to the default theme** when its plugin is absent.
- **Cut from the plan:** the context chooser, user-created `pie.user.*` pies, the pie "More" level, and
  plugin-suggested pie items.
- **The `hello-tool` example is the legacy shared-state style,** not the per-session style that `polygon-tool`
  uses.

The 0.8 limitations (no detail-prop preview, no clipping through a displaced face, concave corners bake
darker than VRAD, no bumped lightmaps, no user manual, and so on) still apply.

## Writing a plugin

Start with `docs/plugins/README.md` and `docs/plugins/getting-started.md`: unpack the SDK, point
`CMAKE_PREFIX_PATH` at it, and use `find_package(ApexPlugin)` with `apex_add_plugin()`. A script plugin
needs only the `.as` file and a manifest.
