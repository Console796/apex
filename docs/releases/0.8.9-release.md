# Apex 0.8.9-release: displacements, overlays and ropes

Apex is a native level editor for Source-engine maps, built for the Strata Source (Portal 2: Community
Edition) toolchain. It reads and writes `.vmf` files, edits them in any number of Vulkan viewports,
compiles them with the real Source tools, launches the game, and previews lighting in the editor.
It is written in C++23 with Qt 6 and Vulkan, it runs natively on Linux and Windows, and it is MIT
licensed.

This release completes milestone 0.8, advanced geometry and surfaces. Since
[0.7.7](https://github.com/Console796/apex/releases/tag/v0.7.7-release), Apex can create, sculpt, paint
and sew displacements, place overlays and decals, texture with hotspots, preview ropes and cables, and
check and select structural geometry.

> ## Please read this!
>
> **Apex is still unfinished, pre-release software.** It is not a replacement for Hammer yet, and it
> will crash, lose your place, or do the wrong thing.
>
> - **Back up every map before you open it in Apex.** Saving an unmodified file is byte-identical,
>   but edits are not guaranteed to be safe.
> - **Some 0.8 release checks are still open.** The written outdoor scenario that defines parity with
>   Hammer++, the interop check of every fixture edited in Apex and reopened in Strata Hammer, and the
>   Windows run of that scenario have not been signed off yet. Treat displacement and overlay editing as
>   new and lightly tested against real maps.
> - **The baked preview is a preview.** It is not VRAD. Compile with VRAD before you judge a map's final
>   lighting.
> - **Only Portal 2: Community Edition has been tested.** Other Source games may work, partly work, or
>   not work at all. See
>   [docs/source-game-support.md](https://github.com/Console796/apex/blob/v0.8.9-release/docs/source-game-support.md).
> - **Windows is less tested than Linux.** The full test suite passes on a real Windows machine, but
>   that machine's GPU has no ray-query support, so the GPU baker has only been tested on Linux.

## New since 0.7.7

**Displacements**
- **Displacement tool** with Create and Sew modes, plus **Sculpt** and **Paint** modes. Every stroke is
  one undo step and is previewed live before it commits. The Smooth brush replaces a separate subdivide.
- **Destroy displacement** turns a displaced face back into a flat one.
- **Face Properties** has a Displacement tab: power, and the NoPhys, NoHull and NoRay flags. Changing the
  power resamples a sculpted displacement instead of flattening it.
- Displacements draw, pick, snap and bound as their displaced mesh. A displacement brush's other sides do
  not exist in game, so Apex hides them too.
- Displacements follow transforms (move, rotate, scale, mirror) and paste, and survive save and reopen.
- **What the other tools do to a displaced solid.** The vertex tool refuses moves of the displaced
  face's corners. Clip refuses only when it would cut the displaced face. Carve, hollow and merge refuse
  and point you at Destroy displacement.
- **Problems** reports unsewn displacement gaps, unreadable displacements, non-quad bases and
  out-of-range alphas.
- **Displacement lighting.** The baker charts and bakes displacement lightmaps on both the GPU and CPU
  paths, and Baked and Hybrid views show them.

**Overlays and decals**
- Overlays and decals draw in the viewport, clipped to the faces they sit on, and are checked against
  the compiled BSP's overlay data.
- The **Overlay tool** places overlays and decals and edits their quads. Dragging previews live and
  commits once, on release.
- Overlays follow their faces when the faces are split, moved, rotated or pasted. Face Properties lists
  the overlays on the active face.

**Hotspot texturing**
- A **Hotspot** button in Face Properties and a **Hotspot** mode in the Apply tool fit a face to a
  rectangle of the material's hotspot set. Hold Alt to use the alternate group.
- Hotspot rectangles come from the VTF hotspot resource or a `.rect` file. The material browser tags
  such materials with an "H".
- The fit rule is Apex's own, because Strata does not publish its scoring. It may choose differently
  from Hammer++.

**Ropes and cables**
- `move_rope` and `keyframe_rope` entities can be placed (the FGD's `MoveClass` and `KeyFrameClass`
  entities were previously not placeable).
- Ropes draw as the engine would hang them: sag from `Slack`, node count from `Type`, smoothing from
  `Subdiv`, drawn as a tube with the entity's `Width` and `RopeMaterial`.
- The **Rope tool** (Tools menu): click points in any viewport and press Enter to create a rope as one
  undo step. Backspace removes the last point and Escape cancels.
- Duplicating a keyframe strings it into its chain, as Hammer does.

**Detail and structural tooling**
- **To Detail** and **To World** (Edit menu, and a new Objects pie on Shift+Q) convert brushes to and from
  `func_detail`.
- A **Structural** overlay greys out everything that is not structural, and the outliner has a
  Structural filter.
- A **SmallStructural** warning in Problems flags world brushes too small to hide a standing player.

**Other changes**
- The Rope tool and the Displacement tool appear in the Tools menu.
- Gizmo drags no longer stall, and an overlay's rotation snaps to the angle step.

## What is missing

- **Detail props are not previewed.** The preview was built and then dropped from 0.8 and will return in a
  later milestone. The hidden code stays in the tree and has no menu entry.
- **Ropes are checked against the SDK's rule, not against in-game captures.** Wind and `Collide` are not
  previewed.
- **No clipping, carving or merging through a displaced face.** Destroy the displacement first.
- **Hotspot thumbnails** may miss the "H" when only the base texture carries the resource. Fitting is not
  affected.
- **Structural tint is lost** on the contents of `func_instance`.
- **Concave corners bake darker** than VRAD (about 0.7× within a luxel of the crease).
- **No bumped lightmaps, no GPU bake on GPUs without ray queries** (NVIDIA GTX 16-series and older bake on
  the CPU).
- **No plugins or scripting** (milestone 0.9).
- **No user manual.** The project documentation is aimed at developers.
- The Linux tarball ships without the Qt Multimedia plugin, so sound preview playback is not available
  from it. The `.deb` and `.rpm` use your system's Qt Multimedia.
- Only the Strata/P2CE game profile exists.

## Downloads

All files are version `0.8.9.79`: milestone 0.8, sub-milestone 9, build 79.

| Platform | File | Notes |
|---|---|---|
| Debian, Ubuntu | `apex_0.8.9.79_amd64.deb` | Uses your system Qt (6.10.2 or newer) |
| Fedora, RHEL family | `apex-0.8.9.79-1.x86_64.rpm` | Uses your system Qt (6.10 or newer) |
| Any Linux, x86_64 | `apex-0.8.9.79-release-linux-x86_64.tar.xz` | Bundles Qt; run `./apex` |
| Windows 10/11, x64 | `apex-0.8.9.79-release-windows-x64.exe` | Installer |
| Windows 10/11, x64 | `apex-0.8.9.79-release-windows-x64.zip` | Portable; run `apex.exe` |

SHA-256 checksums for all five files are in `SHA256SUMS`.

All Linux packages were built on Ubuntu 26.04 and need **glibc 2.43 or newer**. On an older
distribution, build from source.

The Windows files are not code-signed, so Windows SmartScreen may warn when you run them.

You need a GPU and driver with Vulkan 1.3. A GPU with `VK_KHR_ray_query` (most AMD RDNA2 and newer,
NVIDIA RTX, Intel Arc) enables the GPU bake and Realtime indirect. The packages do not include the
Vulkan loader or any GPU driver.

```bash
sudo apt install ./apex_0.8.9.79_amd64.deb
```

```bash
sudo dnf install ./apex-0.8.9.79-1.x86_64.rpm
```

```bash
tar -xf apex-0.8.9.79-release-linux-x86_64.tar.xz && ./apex-0.8.9.79-release/apex
```

Apex needs a game install to be useful. Point it at a P2CE install and open a `.vmf`. The VRAD and
Hybrid views use the game's own `vbsp` and `vrad`.

## Please tell us what breaks

**Please [open an issue](https://github.com/Console796/apex/issues) for anything that goes wrong.**
That includes crashes, maps that fail to open or save, geometry that looks wrong, lighting that does
not match the game, and anything confusing. A rough report is better than none.

A good issue says:

- what you did, what you expected, and what happened instead;
- your OS and version, GPU and driver, and which package you used;
- the game and, if you can share it, the map (or a cut-down map that shows the problem);
- the log, which is in Apex's log panel.

Displacement and overlay reports are especially useful now: a map that Apex opens but saves differently,
a sculpt that reopens wrong in Strata Hammer, or a decal that lands on the wrong face.
