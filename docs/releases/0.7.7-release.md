# Apex 0.7.7-release: baked lighting preview

Apex is a native level editor for Source-engine maps, built for the Strata Source (Portal 2: Community
Edition) toolchain. It reads and writes `.vmf` files, edits them in any number of Vulkan viewports,
compiles them with the real Source tools, launches the game, and previews lighting in the editor.
It is written in C++23 with Qt 6 and Vulkan, it runs natively on Linux and Windows, and it is MIT
licensed.

This release completes milestone 0.7, the baked lighting preview. Since
[0.6.8](https://github.com/Console796/apex/releases/tag/v0.6.8-release), Apex can bake lightmaps with
bounced light itself, show the lightmaps from a real VRAD compile, and keep a VRAD result on screen
while it rebakes only the faces your edits changed.

> ## Please read this!
>
> **Apex is still unfinished, pre-release software.** It is not a replacement for Hammer yet, and it
> will crash, lose your place, or do the wrong thing.
>
> - **Back up every map before you open it in Apex.** Saving an unmodified file is byte-identical,
>   but edits are not guaranteed to be safe.
> - **The baked preview is a preview.** It is close to VRAD on our test map, but it is not VRAD.
>   Concave corners read darker than VRAD, and props and displacements are not baked yet. Compile
>   with VRAD before you judge a map's final lighting.
> - **Only Portal 2: Community Edition has been tested.** Other Source games may work, partly work,
>   or not work at all. See
>   [docs/source-game-support.md](https://github.com/Console796/apex/blob/v0.7.7-release/docs/source-game-support.md).
> - **Windows is less tested than Linux.** The full test suite passes on a real Windows machine, but
>   that machine's GPU (a GTX 1650) has no ray-query support, so the GPU baker has only been tested
>   on Linux. On Windows the bake has been tested on the CPU.

## New since 0.6.8

**Display modes**
- The display modes are now **Wireframe, Textured, Realtime and Hybrid**. **Flat, Baked and VRAD**
  are under Display mode → Advanced. Each mode has a tooltip saying what it shows.
- **Realtime** is the old Lit view, renamed: live lights and shadows that follow every edit at once.
- **Baked** shows Apex's own lightmap bake of the current map, with sky and bounced light.
- **VRAD** shows the lightmaps from the last VRAD compile. Display mode → **Rebuild VRAD Lightmap**
  runs vbsp and vrad in the background on a snapshot of the map, and you can keep editing while it
  runs. The status line says when the result is stale.
- **Hybrid** shows the last VRAD compile, and rebakes only the faces near later edits. Edits show up
  in seconds without a full compile. When an edit changes too much for that, such as the sky, Hybrid
  suggests a new VRAD run.
- **A/B compare.** The viewport menu's "Compare light source" swaps the view between two lighting
  sources, for example Realtime against Baked or Baked against VRAD.

**Apex's baker**
- Lightmaps are charted the way VBSP charts them: `lightmapscale`, face splits and the 128-luxel
  subdivision span.
- Bounce uses each material's VTF reflectivity, and honours the VMT `$reflectivity` override.
- The bake is progressive and incremental. It starts with the faces near the camera. After an edit it
  rebakes the faces the edit affected first, and keeps the rest.
- Brush entities (`func_brush`, `func_wall`, `func_door` and others) and the contents of
  `func_instance` are baked. Each instance placement gets its own lightmaps.
- **GPU and CPU.** On a GPU with Vulkan ray queries the bake runs on the GPU. Otherwise it runs on the
  CPU with Intel's Embree. Display mode → Bake settings chooses Auto, GPU or CPU, and sets the bounce
  count, the bounce rays and how far around an edit Hybrid rebakes. When Auto falls back to the CPU,
  the status line names the GPU and says it has no ray queries.

**Realtime view**
- **Realtime indirect** (Overlays panel): ray-traced irradiance probes give an approximation of
  bounced light, so rooms lit mainly by bounce are no longer near black. It follows light and brush
  edits. It needs a GPU with ray queries.
- **Approximate bounce** (Overlays panel): a constant ambient fill plus screen-space AO. It is a
  cheaper stand-in that works on any GPU.
- Editor-only models no longer cast shadows. Only geometry that reaches the compiled map does: brushes
  and `prop_static` models, as VRAD decides. Lamp helpers, `info_player_start` and similar no longer
  cast. `disableshadows` is honoured.

**Viewports and editing**
- Each viewport's **Overlays...** panel groups its toggles into Scene, Faces, Compile and Lighting,
  with a description of each. New overlays:
  - **Bounds:** each brush's bounding box.
  - **Normals:** a line from each face along its outward normal.
  - **Luxel density:** the lightmap lattice as a checker, one cell per luxel, in Baked, VRAD and
    Hybrid.
  - **Tool textures: fixed brightness:** draws `tools/*` faces unlit in Realtime and Baked.
- The world grid no longer flickers against floors at the same height. Overlays has a shortcut,
  Ctrl+Shift+O, and its popup stays open while you toggle.
- **Command palette:** Ctrl+Shift+P searches the viewport and editor actions.
- The VRAD round trip gives vbsp and vrad the editor's mounted content, so PBR materials from addons
  compile correctly.

**Windows**
- Embree is Intel's prebuilt `embree4.dll` with oneTBB, shipped beside `apex.exe`, with both
  licences.

## How close is the baked preview?

On our reference map (test1), with the default settings:

- **Baked against VRAD:** the median luxel ratio is 0.99, and total energy is 0.95 of VRAD's.
- **Hybrid after moving a pillar:** the median ratio is 1.00. 98.6% of the rebaked ring around the
  edit is within 10% of a full VRAD recompile.
- **Concave corners are darker:** about 0.7× VRAD within a luxel of the crease. This is still being
  investigated.
- **Speed on a mid-range GPU (RX 6600):** a full bake of test1 finishes in 0.16 s, and a Hybrid rebake
  of 220 edited faces in 0.30 s. On the CPU they take about 5.9 s and 3.8 s.
- The GPU and CPU bakers give statistically the same result.

The measurements are in
[docs/plans/0.7.md](https://github.com/Console796/apex/blob/v0.7.7-release/docs/plans/0.7.md).

## What is missing

- **Props and displacements are not baked.** They keep Realtime lighting in the Baked and Hybrid
  views, and the status line says so. Displacements arrive in milestone 0.8.
- **No bumped lightmaps.** The baker writes flat lightmaps only, and the VRAD view reads only the flat
  set.
- **No denoiser.** There was no visible noise at the default settings, so it was dropped.
- **No GPU bake on GPUs without ray queries.** This includes NVIDIA GTX 16-series cards and older.
  They bake on the CPU, which is slower but gives the same result.
- **No overlays or displacements** (milestone 0.8). Maps that use them can be opened, but you cannot
  edit them in Apex.
- **No plugins or scripting** (milestone 0.9).
- **No user manual.** The project documentation is aimed at developers.
- The Linux tarball ships without the Qt Multimedia plugin, so sound preview playback is not
  available from it. The `.deb` and `.rpm` use your system's Qt Multimedia.
- Only the Strata/P2CE game profile exists.

The full plan is in [docs/roadmap.md](https://github.com/Console796/apex/blob/v0.7.7-release/docs/roadmap.md).

## Downloads

All files are version `0.7.7.77`: milestone 0.7, sub-milestone 7, build 77.

| Platform | File | Notes |
|---|---|---|
| Debian, Ubuntu | `apex_0.7.7.77_amd64.deb` | Uses your system Qt (6.10.2 or newer) |
| Fedora, RHEL family | `apex-0.7.7.77-1.x86_64.rpm` | Uses your system Qt (6.10 or newer) |
| Any Linux, x86_64 | `apex-0.7.7.77-release-linux-x86_64.tar.xz` | Bundles Qt; run `./apex` |
| Windows 10/11, x64 | `apex-0.7.7.77-release-windows-x64.exe` | Installer |
| Windows 10/11, x64 | `apex-0.7.7.77-release-windows-x64.zip` | Portable; run `apex.exe` |

SHA-256 checksums for all five files are in `SHA256SUMS`.

All Linux packages were built on Ubuntu 26.04 and need **glibc 2.43 or newer**. On an older
distribution, build from source.

The Windows files are not code-signed, so Windows SmartScreen may warn when you run them.

You need a GPU and driver with Vulkan 1.3. A GPU with `VK_KHR_ray_query` (most AMD RDNA2 and newer,
NVIDIA RTX, Intel Arc) enables the GPU bake and Realtime indirect. The packages do not include the
Vulkan loader or any GPU driver.

```bash
sudo apt install ./apex_0.7.7.77_amd64.deb
```

```bash
sudo dnf install ./apex-0.7.7.77-1.x86_64.rpm
```

```bash
tar -xf apex-0.7.7.77-release-linux-x86_64.tar.xz && ./apex-0.7.7.77-release/apex
```

Apex needs a game install to be useful. Point it at a P2CE install and open a `.vmf`. The VRAD and
Hybrid views use the game's own `vbsp` and `vrad`.

## Please tell us what breaks

**Please [open an issue](https://github.com/Console796/apex/issues) for anything that goes wrong.**
That includes crashes, maps that fail to open or save, geometry that looks wrong, lighting that does
not match the game, and anything confusing. A rough report is better than none.

A good issue says:

- what you did, what you expected, and what happened instead;
- your OS and version, GPU and driver, and which package you used;
- the game and, if you can share it, the map (or a cut-down map that shows the problem);
- the log, which is in Apex's log panel.

Lighting comparisons are especially useful now. The A/B compare between Baked or Hybrid and VRAD
shows a mismatch directly, and a screenshot of each at the same position makes it easy to chase.
Reports of how fast the bake runs on your GPU, and reports from Windows machines with ray-query GPUs,
are welcome too.
