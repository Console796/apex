# Lighting compilation verification — 2026-10-28

Native P2CE Linux VBSP, VVIS (`-fast`) and VRAD (`-fast -StaticPropLighting
-StaticPropPolys`) compiled a temporary snapshot of the reporter's `test1.vmf`.
No Valve/Strata assets or reproduction map are stored in this repository.

The custom `light_rt` at `-1124 -1060 220` omitted `_light`. The inspector displayed
the inherited FGD default `255 255 255 200`, but native VRAD emitted zero worldlight
intensity. Supplying missing FGD light defaults changed its RGB intensity to
`0.7843138 0.7843138 0.7843138`. Nine other nonzero worldlights remained present in
the initial baseline and defaults comparison; the reporter confirmed the elevator
lights work.

VBSP reported `Material not found!: pbr/metal/black_tile_64` with the original
game directory even though the editor and game mounted EverythingPBR. The surface
received texinfo flags `0x400` (`SURF_NOLIGHT`). The installed VBSP rejected
`-mountmod`, including attempts to pass it after the map argument.

Apex now generates a temporary gameinfo from its actual ordered VFS mounts,
retaining engine metadata and anchoring original game paths. Compile tools receive
this directory; game launching and BSP installation retain the real game directory.
The installed gameinfo, addon lists, and source VMFs are unchanged.

The final native run used a snapshot generated by the implementation and passed
all three tools. The custom light had nonzero intensity as above; the PBR surface
received flags `0x820` with `SURF_NOLIGHT` absent, and the BSP contained 81,156 HDR
lightmap samples, 53,125 nonzero. Recompiling is required to replace the old BSP.

Regression verification: 32 targeted tests / 23,540 assertions, 158 offscreen UI
tests / 4,277 assertions, and a successful application/test build. The targeted
suite includes the installed FGD and reproduction map via opt-in environment
variables, plus synthetic tests for default preservation, undo, copied instances,
addon precedence, and separation of compile and game launch paths.
